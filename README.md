# Pixel Rally · Palm Island GP

俯视像素自动赛车游戏。原生 Node.js + Canvas，零 npm 依赖。新版按用户提供的明亮泥地赛车参考改成热带赛场，默认约 3 倍近距离跟车，支持全景切换、小地图、圈数和排名 HUD、永久保留一段时间的胎痕、粒子白烟、冲刺镜头拉远和方向速度线。

## 启动与预览

安装 Node.js 22 或更新版本，在本目录打开终端：

```sh
node server.mjs
```

打开 http://127.0.0.1:3000 。创建房间，复制邀请链接；其他浏览器输入房间码加入。房主开始后同步倒数 3 秒，比赛共 3 圈。不足 6 人会补 AI，真人最多 12 人。可在同一浏览器的多个标签页分别输入名字加入；每个标签保留自己的车手身份，也可以用不同设备。

手机和电脑在同一局域网时，访问 `http://电脑局域网IP:3000`。须允许系统防火墙访问该端口；分享链接必须使用对方能访问的地址，localhost 链接只能本机使用。

## 操作

- 自动驾驶，无需方向键。
- `1` / 点击 NITRO：1.8 秒冲刺，冷却 6.5 秒。
- `2` / 点击 MISSILE：攻击前方 460 米内最近对手，导弹飞行 650 毫秒后命中，使其减速 1.8 秒，冷却 8.5 秒；护盾可抵挡。范围内没有目标仍消耗冷却。
- `3` / 点击 SHIELD：护盾持续 3 秒，冷却 10 秒。
- 在 S 弯入口冲刺可切入实际的斜向捷径，避开连续弯道；捷径路线和进度由服务端决定。加速路段自动提速，技术弯和施工路障减速。
- SPORT 均衡；BUGGY 基础速度略快；VAN 略慢。这是可扩展的原型数值，尚未做竞技平衡。
- `4` / EMP：150 米范围内对手减速并显示电击 1.1 秒，冷却 12 秒，护盾可抵挡。
- `5` / OIL TRAP：留下 9 秒油迹，同车道后车经过时打滑减速 1.9 秒，冷却 9 秒，护盾可抵挡。
- `6` / FREEZE：对前方 400 米内最近车辆发射冰冻射线，减速 2.8 秒，冷却 11 秒，护盾可抵挡。
- SOUND 开关启用用户提供的引擎 MP3 与合成技能音效；Nitro 会改变引擎播放速度和音量。音频由用户提供，文件为 `public/engine.mp3`。
- 赛道右上角可切换跟车/全景，或退出当前会话建立新比赛。
- 比赛中可用房间码观战；刷新页面用本地保存的会话恢复原车手。
- 完赛显示最终成绩，房主可重赛。

## 同步与规则

服务器以 20 Hz 统一推进比赛：车辆路程、圈数、技能冷却、命中、赛道速度、终点时间均由服务端决定。浏览器仅发送创建、加入、开始和技能指令，不接收客户端提交的位置或排名。

使用同源 HTTP POST 上行、SSE 下行。SSE 自动重连，并读取最新完整快照；前端有限外推平滑显示。断线车继续自动行驶，恢复后接回原身份。会话 token 保存在当前标签的 sessionStorage；快照不包含 token。输入名字安全转义，限制请求体大小。观众无法施放技能，非房主无法开始比赛。

赛道、棕榈树、广告牌、车辆与技能用 Canvas 程序绘制。新版按用户后续提供的泥地像素赛车图片调整视觉，没有直接使用图片作为游戏背景。外部字体不可用时自动回退系统字体，游戏不受影响。

## 测试

无需开放端口的规则测试：

```sh
node --test test/combat.test.mjs
```

完整网络集成测试须先启动服务，再运行：

```sh
node --test
```

集成测试会创建 12 个真实独立会话，验证满员、房主权限、同步倒数、技能冷却、观众权限、重连身份、完整 3 圈结算和重赛，耗时约 2 分钟。可设置 `TEST_URL` 测试已部署服务。

## 部署：单实例 Node 主机

将此目录上传到支持常驻 Node 服务的主机，启动命令 `node server.mjs`，无构建或依赖安装步骤。服务读取平台的 `PORT`，绑定 `0.0.0.0`。仓库附 `render.yaml` 和 `Dockerfile`，可按托管平台的 Node 或容器流程部署。部署后分享 HTTPS 域名的房间链接。

容器运行示例：

```sh
docker build -t pixel-rally .
docker run --rm -p 3000:3000 pixel-rally
```

反向代理必须支持长连接 SSE，关闭代理缓存和缓冲，并给读取超时至少 120 秒。例如 Nginx 的 `/events` 路径配置 `proxy_buffering off; proxy_read_timeout 1h;`。HTTPS 在平台或反向代理终止。

## 当前版本范围

这是可玩多人原型，不是生产运营后端。房间和成绩保存在单进程内存；服务重启会丢失，最后一次房间操作 1 小时后过期。须使用单实例；水平扩容需迁移到共享房间服务。包含令牌身份和基本输入限制，尚无账号、全局限流、持久化或匹配系统。房主断线后可重连接续操作，尚无自动移交房主。赛车沿预设路线自动行驶，技能按服务端路程命中，未实现刚体车辆碰撞；捷径沿独立斜向路线运行。漂移烟雾和技能粒子是表现效果。

手机布局已实现；真实触屏与跨公网延迟仍需部署后实机验收。Sites 静态托管不能直接运行此常驻 Node 比赛服务，请使用上述 Node/容器部署方式。

部署平台参考：[Render Web Services](https://render.com/docs/web-services)、[Blueprint YAML](https://render.com/docs/blueprint-spec)。

## 本轮验证限制

新增六技能规则测试 5 项通过，使用实际生产请求处理器和比赛推进函数，通过模拟时钟验证，不依赖网络端口。客户端真实绘图代码执行 80 帧，覆盖跟车、冲刺、护盾、冰冻、EMP、油迹和爆炸，无运行错误。本轮环境禁止服务器越过沙箱启动；旧预览服务已停止，需双击 Start-game.cmd 重新启动。新版尚待浏览器实玩及音频主观听感验收。

## 加宽加长与引擎修正

赛道世界扩大到 2304 × 1480，路面实际宽度和单圈路程均为前一版的两倍；近距离镜头不随全图尺寸缩远。车辆排位间隔也扩大。新赛道要求重启服务器，客户端会检测旧版赛道并提示，避免不同版本产生位置错乱。

引擎不再循环播放整段原始 MP3。客户端解码一次，分析录音选取稳定段，做交叉淡化衔接；播放速率和滤波随服务端车速变化，冲刺增强，完赛静音，关闭声音或切到后台淡出。声音处理的单元测试验证了衔接、车速控制、完赛及静音；真实听感仍需试玩验收。

## 节奏与声音更新 v3

基础速度从 100 提高到 220 个赛道单位/秒；Nitro 改为 1.4 秒、1.55 倍速度，冷却仍为 6.5 秒。后车在 95 个赛道单位内获得 10% 尾流提速，落后车另有最多 32% 的距离追赶加成；服务器计算真实路程，未直接改写排名。自动选择相邻车道超车。速度表与客户端外推使用服务端实际速度。

原 MP3 已不再作为持续引擎底声循环或变调。它只用于起跑和 Nitro 的 1.1–1.4 秒原速短音效，带淡入淡出；持续背景仅为低音量风声，完赛、静音、后台时淡出。实际音色需实玩评价。

新增追赶测试：同车型两车一次 Nitro 后距离约 108 单位，6 秒后后车追上；合计 8 项规则/音频测试通过。v3 需要重启服务器并刷新页面，新房间才会使用新的比赛数值。

Windows 启动器现在使用 http://127.0.0.1:3001，并启用 Node 自动重载，避开已运行的旧版 3000 服务。手动执行 node server.mjs 仍默认使用 3000。自动重载比赛服务后内存房间会重置，页面会提示重新创建房间。


## 当前比赛规则（v4，取代前文旧版数值）
每场技能总次数：Nitro 3、Missile 3、Shield 2、EMP 1、Oil Trap 2、Freeze Ray 2。次数由服务器扣除，按钮显示余量；冷却结束或重连不会补充，重赛才重置。
车辆按四列分排起步；同车道保留安全间距，有空位才换道超车。追赶提速仅在落后超过 140 距离单位时触发，最多 18%，避免把近距离车辆挤成一团。
更新后刷新页面并创建新房间。请使用 Start-game.cmd 打开的 3001 地址；自动重载会清空旧房间。

## v5 两站巡回赛（当前规则）
开赛自动补满 12 台车。第一站热带泥地 3 圈，完赛显示成绩 8 秒后自动切换到第二站雪夜山道，同步倒数后再跑 3 圈。第二站完赛结束，房主可重新开始整个巡回赛。每站重置技能次数；跨站保留同一车手和房间，观众/重连可直接接入当前站。
车辆重绘为带黑色外轮廓、挡风玻璃、车灯、轮胎和车身条纹的俯视像素车。行驶底声换成用户提供的车内加速录音，完整原速播放，重播时交叉淡化；比赛外、完赛、静音和后台停止。创建/加入/开赛点击解锁浏览器声音，浏览器刷新后可能需要再次点击声音按钮。
